01 / Thesis

A plausible answer is not enough

Frontier AI models can often get surprisingly close to a useful award interpretation. But a plausible answer is not enough. The reasoning can be difficult to trace, assumptions may be hidden, and there is often no practical way to review how an individual rule was derived from the source.

Award Extractor explores a more structured approach: AI suggested, human edited.

  • AI suggestedThe model proposes structured payroll rules from the award.
  • Human editedA reviewer can accept, modify or reject the proposed interpretation.
  • Traceable outputRules stay linked to source clauses so the interpretation can be inspected and challenged.

The aim is not to replace human interpretation. It is to test whether AI can accelerate the difficult first pass while keeping the result traceable, reviewable and suitable for further assurance.

The current experiment produces one Award Interpretation covering overtime creation, overtime consequences and penalties.

02 / Method

From award text to reviewed rule

The process begins with the award text and progressively turns model suggestions into a human-reviewed interpretation. Open a step to see what happens, what is produced, and what a reviewer can check.

1Fetch and structure the awardSource record

Retrieve the award from FWO, or use the supplied PDF. Parse the document into headings and clauses and write a structured JSON snapshot. No interpretation is performed at this point.

Output
Structured award JSON and source snapshot
Review point
Does the structure match the original award?
2.1Classify payment-relevant clausesLLM + deterministic checks

Classify each top-level clause as payment-relevant, definition-relevant or not relevant. For relevant direct subclauses, identify the payment type, such as overtime, penalties, allowances, breaks or leave.

Output
Payment classification JSON
Review point
Are all clauses accounted for, including exclusions?
2.2Build the selected ruleset subsetLLM + deterministic checks

Select clauses for the overtime and penalties rulesets. Within overtime, distinguish clauses that determine when time becomes overtime from clauses that apply after overtime has occurred. Identify the relevant employee cohort and work arrangement where the award supports it.

Output
Ruleset clause-classification JSON
Review point
Why is each clause in this ruleset, and for whom?
3.1Draft and combine the rulesetLLM activities + checks

Two independent LLM interpretations turn the shortlisted clauses into payroll rules. A comparison call proposes how differences should be reconciled. The drafts and comparison are combined into a draft ruleset.

Output
Expert drafts, comparison and combined ruleset files
Review point
Are disagreements, clause coverage and cohort differences visible?
3.2Adversarially review the draftLLM evaluator + creator

An evaluator reviews the combined ruleset against the clause evidence. A creator records whether each recommendation is kept, modified or removed, records additions, and rebuilds the revised ruleset.

Output
Evaluator findings, creator decisions and revised ruleset
Review point
Are silent removals and unsupported additions prevented?
4.1Format the guideLLM + coverage warning

Reorganise the reviewed ruleset into a guide that a payroll officer can read. Compare the source and formatted versions so that missing rules are flagged rather than silently lost.

Output
Formatted Markdown guide and coverage warnings
Review point
Are the key rules, thresholds, scope and citations still visible?
4.9Create the human working copyHuman review

A reviewer can correct the guide in a Markdown working file. That reviewed file becomes the preferred source for the next stage, with the change kept visible.

Output
Human-reviewed ruleset Markdown
Review point
What did the reviewer change before implementation?
5.1Generate pseudocodeLLM + rule inventory

Translate the latest reviewed source into pseudocode. Check that the source rules, required inputs, exclusions and clause references are represented in the implementation draft.

Output
Pseudocode and validation files
Review point
Which reviewed rule, if any, is missing from the logic?
6.1Project the rules into a calculatorLLM + evidence

Load the three rulesets in the Award Interpretation and use them to answer a fixed calculator questionnaire and draft Python. This is a projection of the interpretation, not a replacement for it.

Output
Calculator questionnaire JSON and Python draft
Review point
What evidence supports each calculator answer?
03 / Controls

How the answer stays reviewable

ProposeAI suggestions classify clauses and draft interpretations.

TestDeterministic controls check structure, coverage, references, duplicates and required fields.

DecideHuman review tests the interpretation against the award and edits it before implementation.
